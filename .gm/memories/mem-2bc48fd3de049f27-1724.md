gmsniff information-tiering mechanics (drained from AGENTS.md; the binding rule "the daily-first tiering is deliberate -- do not flatten, merge or re-alphabetize it as cleanup, and the two subsystem literals must stay identical" stays resident there, these are the details behind it). The GUI sidebar is built by renderShell in gui/app.js and the CLI help by printHelp in src/cli.js, both tiered daily-first for the observer: the live-agents/manager view leads, then Daily, then Investigate; the Subsystems, Analytics and Control panels sit behind a collapsed-by-default "Show advanced" toggle whose state persists in localStorage key gmsniff.nav.advanced and is whitelist-validated on read. Demoted panels stay reachable through the Ctrl+K command palette and #panel= deep links, which auto-expand the collapsed group for that session only. On the CLI side --help opens with QUICK START ahead of INVESTIGATION/DIAGNOSTICS/AGENT-FACING, and every --schema subcommand carries a matching `tier` field so the machine-readable surface mirrors the human one. Separately: src/index.js SUBSYSTEMS is the hardcoded seed for the subsystem-tag universe and gui/panels.js SUB_LIST seeds from the identical literal, duplicated deliberately because the browser bundle cannot import the Node module (zero build step, zero dependencies). Both lists grow at runtime from the Dashboard component's snap.observedSubsystems merge when a genuinely new tag appears in real data, so a tag missing from the literal is not necessarily missing from the UI. Never add or remove a subsystem tag in either list without confirming against current ../gm source and recent real watcher-log data, and never let the two literals drift apart from each other.
