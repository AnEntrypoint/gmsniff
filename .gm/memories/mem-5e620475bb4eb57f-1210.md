The gm browser verb evaluates its body in the PAGE context (cdp-eval), NOT in a Playwright driver context. A body calling page.evaluate/page.goto/page.waitForTimeout fails with "ReferenceError: page is not defined" and looks exactly like a broken/unavailable browser verb -- a gmsniff session previously burned 8+ retries on this and recorded a false blockedBy:external mutable, then fell back to curl + node --check substitutes for every client-side witness. The correct body is browser-context JS: prefix lines like "url=http://host/path" and "timeout=90000" are parsed by the watcher, then the remaining body runs INSIDE the page with bare document/window access and a plain `return`. Witnessed both halves against the live gmsniff GUI: body with page.evaluate -> exit_code 1, stderr "cdp-eval: exception ReferenceError: page is not defined"; identical URL with `return {title: document.title, bodyLen: document.body.innerHTML.length}` -> exit_code 0, real DOM values. Use `await new Promise(r => setTimeout(r, ms))` instead of page.waitForTimeout. Browser dispatches take 2-6s, so a first-read miss on the out file is normal -- wait on file existence, never conclude the watcher is dead from latency alone.
