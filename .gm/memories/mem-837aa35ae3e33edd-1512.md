gmsniff observability doctrine, established across two user corrections: report measurements, never bake in a verdict, and the line that decides borderline cases is whether anything becomes UNREACHABLE. stuckProjects was wrong because it counted breaches against hardcoded thresholds (15min stale, 10 rows backlog, 5 deviations/min), summed invented weights into a severity, and returned only projects scoring above zero -- so a condition the thresholds did not anticipate was invisible, not merely unranked, and a project one second under a cutoff rendered identically to a healthy one. The GUI health banner had the same shape (four HEALTH_ constants collapsed to red/amber/ok, then filter(r => r.severity !== ok) dropping rows) and was replaced with the measurements themselves: 3 working agents, longest-silent first, each row naming watcher state, silence duration and deviation rate. What is LEGITIMATE and must not be stripped: ranking a COMPLETE list with each contributing reason named (attentionScore orders but drops nothing); a presentation-only cap that states what it omits (2 shown / 66 discovered, +64 hidden -- pass --idle); reporting ANOTHER systems classification (gm own documented recovery verb per deviation kind, the severity gm writes into its own prd.yml); and naming a real causal chain the data implies (embed failures cascading into dropped vector hits so codesearch silently answers from bm25 only). Ranking with everything visible is reporting; scoring that omits rows is a verdict.
