gmsniff test.js harness mechanics (drained from AGENTS.md; the binding rule "extend that one file, never add a second test file or a test/ directory or a testing library" stays resident there). There is no test framework and no test/ directory: test.js at the repo root is the single mock-free real-services integration test, run as `node test.js`. It spins up a real temp log dir, constructs a real GmLogWatcher and MultiProjectWatcher, writes real jsonl lines to disk, and asserts against real SSE and replay output -- no mocks, no fixtures library, no assertion library, because zero-dependencies is load-bearing for gmsniff (it must install and run air-gapped and must never become a supply-chain surface for the agent host it observes). New coverage is added by extending this one file. It is also the ONLY gate between a push and an npm publish: .github/workflows/publish-npm.yml runs `node test.js` with no install step before bumping and publishing, which additionally proves the zero-dependency property on every push, since a green run with no node_modules present means nothing was required. Measured output shape on a healthy run: "gmsniff OK — <N> events across <N> days · live-feedback verified · multi-project fanout verified · formal-spec verified · stuck-state+throughput+memory-health+codeinsight-age verified · total-parser verified · watcher-log-total-parse+source-priority+correlation+project-state verified", exit code 0. Keep exact-count assertions scoped to a fixture cwd rather than the fleet: GM_SPOOL_DIRS ADDS a discovery root and does not restrict discovery (C:/dev and process.cwd() are always scanned too), so a fleet-wide total assertion is machine-dependent and fails elsewhere.
