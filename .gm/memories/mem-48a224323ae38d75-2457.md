gmsniff gui/ds vendoring mechanics (drained from AGENTS.md; the binding rule "never hand-edit gui/ds, fix upstream then sync, and vendor the whole import closure" stays resident there, these are the operational details behind it). gui/ds/ is vendored byte-for-byte from the sibling repo ../anentrypoint-design via scripts/sync-ds.mjs, copying exactly the paths listed in the VENDORED_PATHS_RELATIVE_TO_BOTH_ROOTS flat list. Editing a file under gui/ds/ directly is silently reverted by the next `npm run sync:ds`; the correct order is fix in ../anentrypoint-design, `npm run sync:ds` to pull it down, `npm run sync:ds:check` to confirm zero drift, then commit. WHY vendored rather than an npm dep or a live import: gmsniff publishes as an installable package (bin: gmsniff, files: ["src/","gui/"]) that must run standalone via npx with no guarantee the sibling checkout exists, and src/server.js serveStatic() serves gui/ as static files with no bundler and no request-time node_modules resolution -- so a live filesystem import from ../anentrypoint-design breaks exactly that distribution path. An npm dependency does not fit either: anentrypoint-design's exports map exposes ./dist/247420.js (a single-file bundle whose CSS classes are all scoped under .ds-247420) plus a few named kit subpaths, but NOT the raw src/components/*.js or src/theme.js files this directory uses, nor the unprefixed root *.css files gmsniff's markup expects (ds-panel, ds-stat, etc. with no .ds-247420 ancestor). So: vendor the raw unprefixed component sources, never the upstream dist/ bundle, never via the exports map. The sync is deliberately NOT wired into npm install/prepare, because that would make installing gmsniff require a sibling checkout. Packaging note: package.json files ["src/","gui/"] ships everything under both trees plus package.json and README.md, so any new module or asset is included automatically -- but a PARTIAL vendor is not caught by packaging, it is caught by the import-closure rule; verify with a real `npm pack --dry-run` after adding or vendoring files, since the published tarball is all an installed user has. The concrete failure this prevents: gui/ds/app-shell.css is a manifest of @import url('./src/css/app-shell/*.css') containing no rules of its own, and its seventeen targets had never been vendored -- every rule it referenced was silently inert behind 404s with no error and no console warning, looking exactly like a design bug.
