A comment-elimination pass over a real codebase is also a dead-code audit and a latent-bug audit, and that is the strongest argument for doing it. Measured on gmsniff: 2314 comment lines to 1354 (41 percent), and the pass surfaced 10 unreachable surfaces (routeSend, readNumberFile, FSM_GATES, send_, parseRel, ID_LINE, loadState, capabilitiesLoaded, resetLiveState, a never-read _openDispatch field) plus THREE latent bugs where code read fields its producer never returns. projectSignals read gateState.failing, which readFsmGates never returns, so gates_failing was empty for EVERY project until fixed -- afterwards 44 of 161 report real blockers. healthSummary read liveness.daemon_pid_alive and daemon_shared, neither defined, serializing undefined on every row. Every one was invisible precisely because the surrounding prose described the intended behavior confidently enough that nobody checked the field names against the producer. The sharpest case: a loadState helper whose comment called itself the through-line of this rework and claimed every panel built one, with zero call sites -- the prose asserted an architecture the code did not have.
