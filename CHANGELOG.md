## 2026-07-28 — Drain AGENTS.md into the recall store and correct the refuted browser blocker at its source

- **Discharge the drain obligation plugkit had been flagging**: the memorize store reported that AGENTS.md had not shrunk across eleven consecutive `memorize-fire` calls, so facts were flowing in and never out. The `gui/ds` vendoring rationale and the information-tiering mechanics — operational detail that is recall-reachable rather than needed resident on every prompt — were fired to the store and their paragraphs compressed to pointers, taking the file from 20,526 to 18,807 bytes. Each compressed section keeps its binding rule inline; only the mechanics moved. Both directions were witnessed rather than assumed: the two memories embed, and a natural-language query for each returns it as the top hit (0.798 and 0.653), so the material is reachable and not merely stored.
- **Correct the refuted browser-verb finding on the mutable row itself**: the row still asserted a reproducible environmental gap and prescribed `curl` and `node --check` as substitute witnesses, which a future session reading the store would have re-trusted. It now names the real cause — the verb evaluates in the page context — alongside the evidence that refuted it.
- **Record that `mutable-add` appends where `prd-add` upserts**: re-scoping the mutable by id silently produced a second row under the same id, leaving the refuted claim and its correction side by side as separate rows, with nothing erroring. The duplicate was removed with a script that aborts unless the row it keeps carries the corrective text. gmsniff's own `rewriteRow` was tested against a real fixture and does not share the behavior: it upserts in place, leaves sibling rows byte-identical, and returns `null` for an unknown id rather than appending one.

## 2026-07-28 — Re-examine the declined rows and correct a false browser-verb blocker

- **Record that the `browser` verb evaluates in the page context, not a driver context**: a prior session concluded the verb was environmentally unavailable after eight failed dispatches and recorded an external blocker, then witnessed every client-side change through `curl` and `node --check` instead. The verb works — a body calling `page.evaluate` fails under `cdp-eval` with `ReferenceError: page is not defined`, while the same URL with bare `document` access returns real DOM values. Both halves were re-run against the live GUI this session, and AGENTS.md gains the trap as a fourth verification failure mode because it reads exactly like a broken tool.
- **Reject the panel-state registry on a measured enumeration rather than leaving it deferred**: the refactor was previously declined for want of a witness. Enumerating every module-level declaration across the seven GUI modules found 25, already partitioned per panel — `codesearchState`, `consoleState`, `treeUiState` and the rest are owned by exactly one panel each, and the nine bare bindings are module-private render/transport machinery. Hoisting them into one registry would widen the single-writer surface for no measured benefit, so the current shape stands.
- **Restate the per-project concurrency finding on corrected grounds**: the first re-measurement scanned 141,710 lines for a `run` field and reported zero interleaved epochs, which was not evidence of anything — the pattern matched nothing. Enumerating the real `evt` key universe showed no `run` and no `sess` field on any record, so per-agent concurrency is structurally unmeasurable from the watcher log, which is why `src/correlation.js` falls back to a bare `cwd` key and why the one-row-per-cwd manager view is correct for this source.
- **Confirm the `likely_orphaned` index hint is a false positive with no consumer**: `apiPost` and `fmtTs` were flagged as orphaned by a partial index covering four files; they have 7 and 10 real call sites respectively, and no gmsniff surface reads the hint.

## 2026-07-27 — Invert the event source, model the real telemetry stream, and rebuild around the live manager view

- **Make the per-project spool the primary event source and the central archive opt-in**: `~/.claude/gm-log` stopped receiving writes when gm moved to the shared daemon, so reading it as primary meant every count gmsniff reported was computed over dead history while live agents were running. `replayAllAudited` now returns `source: "spool"` with `archive_used: false`, and the archive is read only on an explicit request or an operator-set `GM_LOG_DIR` — never silently merged, because a silent merge makes the numbers larger and therefore more convincing while being entirely wrong.
- **Parse the non-JSON lines in `.watcher.log`**: only about 15% of the file was `evt: {json}` and the rest was being discarded, which meant the dispatch-start stream had no representation at all — the log records a dispatch ending but never an upstream event for it beginning. `src/watcher-log.js` now models dispatch lines into synthesized `dispatch.start` events, plus wasm version banners, spawn boundaries, stale-lock takeovers and retention sweeps, and reports its own coverage so a future parser regression is visible rather than silent.
- **Add `src/correlation.js` with a ranked identity**: there is no universal session key in the data, so grouping by an assumed one silently invented sessions that did not exist. Events are now keyed by the best identity actually present — `sess`, then `session_id`, then `cwd#run`, then `cwd` — and surfaces report which one they used so a run-keyed group is never mistaken for an agent session.
- **Separate the three meanings of liveness**: `alive` previously meant "the shared daemon responded", which was true for every project on the machine and therefore told an observer nothing. `discoverProjects().alive` now means this project is actually working, with `daemon_alive`, `last_activity_age_ms`, `queue_depth`, `phase` and `last_skill` alongside it.
- **Stop treating `.status.json`'s `ts` as a per-project heartbeat**: the shared daemon rewrites that field for every project it serves several times a second, so it read as fresh for projects idle for days and made stale projects look busy.
- **Widen project discovery through the daemon registry**: a one-level directory scan could not see worktree-hosted projects, so the great majority of real agents were invisible. Discovery now seeds from `~/.gm-tools/daemon-registry.txt`, the daemon's own served-cwd list, filtered against real filesystem existence because that file is append-only and never prunes entries for deleted directories.
- **Read `.gm/turn-state.json` as the primary phase source**: phase was being regex-scraped out of `next-step.md` prose when the runtime writes it as a structured field, which drifted whenever the prose changed. The state files (`last-prompt.txt`, `last-dispatch-ts`, the zero-byte existence markers, `.last-gate-fired.json`) are now read directly, with gate age always shown so a days-old last-ever gate is never displayed as a current block.
- **Track gm's real FSM including its re-plan edges**: EXECUTE→PLAN, EMIT→PLAN and VERIFY→PLAN are legal gate-free transitions, so phase walks computed by linear index math were reporting skipped phases that never happened.
- **Adapt to the agentplug shared-daemon status shape**: `.status.json` lost `version`, `wrapper_sha`, `idle_limit_ms` and `busy_until`, and its `pid` became a machine-wide shared pid, so per-project version reporting had to move to `~/.gm-tools/` and the wasm banner lines.
- **Vendor the `gui/ds/src/css/app-shell/` parts**: `gui/ds/app-shell.css` is an import manifest with no rules of its own, and its seventeen targets had never been vendored — every rule it referenced, including the styling for already-vendored components, was silently inert behind 404s with no error anywhere. Also vendored `sessions.js`, `context-pane.js`, `files.js`, `form-primitives.js`, `interaction-primitives.js` and `virtual-scroll.js`; the markdown/Prism chain is deliberately excluded because it fetches from a CDN and the GUI must work offline.
- **Lead the CLI and GUI with the live manager view**: `gmsniff --agents` shows every working agent's phase, served instruction, time-in-phase, pending counts and streaming recent output in one screen, hiding idle and COMPLETE agents by default, because "which of my agents is doing what right now" is the question the tool exists to answer.
- **Rewrite README.md and AGENTS.md against the measured system**: both documented the central archive as the live source and the wrong path for it, describing the polarity backwards. AGENTS.md now carries the new invariants worth guarding — spool-primary, the status-heartbeat trap, ranked correlation, zero dependencies, the offline-GUI rule and the vendored-import-closure rule.

## 2026-07-24 — Formal verification discipline: schema versioning, resource bounds, monitoring surface

- **Specify event schema versioning**: Every parsed event now carries `_schema: "v1"` — consumers can reject unknown schema versions rather than silently misinterpreting shape changes. Stamped in all five event sources: GmLogWatcher._line, ProjectLogTailer._line, replayWatcherLog, replayAll, and live SSE broadcast.
- **Add resource bounds to Store**: MAX_EVENTS (1M, env-overridable via GM_MAX_EVENTS) with EVICT_BATCH (5k) oldest-event eviction when the cap is exceeded; MAX_SSE_CLIENTS (50, env-overridable via GM_MAX_SSE_CLIENTS). Eviction stats (evictedCount, evictedBatches, maxEvents) exposed in /api/snapshot.
- **Add info-flow label infrastructure**: X-Info-Label response header classifies every API route's data sensitivity (public/project-local/session-local/internal). Route manifest in INFO_LABELS constant.
- **Add three new monitoring endpoints**: /api/spool-queue (pending dispatch count per verb per project), /api/watcher-versions (per-project watcher liveness/runtime/version), /api/instruction-tiers (distribution of vendored/source-synced/default instruction resolution across all projects).
- **Formal specification**: .wfgy/spec/gmsniff-formal-spec.md covers 8 modules (Event Parser, Event Store, Project Registry, API Server, Resource Bounds, Versioned Schemas, Performance Contracts, Missing Monitoring Surface) with pre/post-conditions and invariants in dependent-type style.
- **Test coverage**: All existing tests pass; new formal-spec coverage verifies schema version on snapshots, live SSE events, and all three new endpoints.
